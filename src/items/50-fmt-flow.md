業務フローや処理の流れを図にするときは、次の「フロー記法」で書いてください。
座標や見た目は書かないでください。配置は描画ツールが自動で行います。
記法は **言語名を `flow` にしたコードブロック**（```flow で始めて ``` で閉じる）に入れてください。
図だけを頼まれたときは、そのコードブロックだけを返し、説明文は付けないでください。
文書の中に図を入れるときも同じコードブロックを使います（gemini-agent の文書タブが図にします）。

# 書き方
```flow
title 受注処理フロー（現行）
lane 顧客
lane 営業部
lane 基幹システム

start S @顧客 発注を決める
task A @顧客 注文書を送付
task B @営業部 注文内容を確認
decision C @営業部 不備はあるか
data D @基幹システム 受注データ登録
doc E @基幹システム 出荷指示書
end Z @顧客 商品を受け取る

S -> A -> B -> C
C -> A : あり
C -> D : なし
D -> E -> Z
E ..> B : 控えを送付
note C 不備の基準は別紙
```

# 規則
| 行の種類 | 書き方 | 意味 |
|---|---|---|
| タイトル | `title 文字` | 図の題名（省略可） |
| レーン | `lane 名前` / `lane 名前 {区分}` | 担当者・部署・システム。上から順に並ぶ。区分は下の「処理の区分」 |
| ノード | `種類 ID @レーン ラベル` / `種類 ID @レーン {区分} ラベル` | ID は半角英数字（例：A, B2, S1）。ラベルは日本語で15字程度まで |
| 矢印 | `ID -> ID` / `ID -> ID : ラベル` | 連続して `A -> B -> C` とも書ける |
| 点線の矢印 | `ID ..> ID : ラベル` | 情報・書類の流れ、後日の処理など |
| 注記 | `note ID 文字` | 図の下に ※番号で載る |
| コメント | `# 文字` | 無視される |

# ノードの種類
| 種類 | 形 | 使いどころ |
|---|---|---|
| `start` | 角丸（淡色） | 開始 |
| `end` | 角丸（濃色） | 終了 |
| `task` | 四角 | 作業・処理 |
| `decision` | ひし形 | 分岐。出る矢印には必ず `: はい` `: いいえ` などのラベルを付ける |
| `data` | 平行四辺形 | データの登録・入出力 |
| `doc` | 書類 | 帳票・書類の出力 |
| `sub` | 二重線の四角 | 別のフローで詳しく書く処理 |

# 処理の区分（AI・ルール・人・外部）
誰（何）がその処理をするかを `{区分}` で書くと、区分ごとに決まった色で塗られ、箱の左上に区分名が付きます。
色はどの図でも同じです（As-Is と To-Be で同じ区分は同じ色）。区分を書いた図では、レーンの色は灰色にそろいます。

| 区分 | 書き方 | 使いどころ | 分岐（decision）に付けたとき |
|---|---|---|---|
| AI | `{AI}` | 生成 AI・LLM・AI エージェント（Copilot Studio など）が読み取り・要約・判断する処理 | AI判断：AI が内容を見て決める |
| ルール | `{ルール}` | Office Scripts・Power Automate・マクロ・システムなど、決まった規則で動く処理 | ルール判定：明確な条件（値・有無・範囲）で決まる |
| 人 | `{人}` | 人が確認・判断・入力する処理 | 人の判断：担当者が見て決める |
| 外部 | `{外部}` | 顧客・取引先・他社システムなど、こちらで動かせない処理 | 外部の判断 |

```flow
title 申請書の受付（新）
lane 申請者 {外部}
lane AI エージェント {AI}
lane Office Scripts {ルール}
lane 担当者 {人}

start S @申請者 申請書を提出
task A @[AI エージェント] 書類の項目を読み取る
decision B @[AI エージェント] 書類の種類を判別できたか
decision C @[Office Scripts] 必須項目はそろっているか
task D @[Office Scripts] 台帳に登録
task E @担当者 読み取り結果を確認して直す
end Z @担当者 受付完了

S -> A -> B
B -> C : はい
B -> E : いいえ
C -> D : はい
C -> E : いいえ
E -> D
D -> Z
```

- `lane` 行の末尾に付けると、そのレーンのノードすべてがその区分になる
- ノードは `@レーン` の後ろに付ける（`task F @[Office Scripts] {人} 例外を手で登録`）。ノードの区分はレーンの区分より優先する
- 書類の内容による分岐は、**AI が判断するのか（`{AI}`）、明確な条件で判定するのか（`{ルール}`）を必ず書き分ける**。ルールで判定できるものを AI に任せない
- To-Be（新しい業務）の図では、すべてのノードに区分が付くようにする（レーンに付ければ足りる）。As-Is も、同じ担当には同じ区分を付ける


# 守ること
- すべてのノードにレーン（`@レーン名`）を付ける。レーンを使わない図なら `lane` 行も `@` も書かない
- レーン名は `lane` 行と一字一句同じにする（空白を含む名前は `@[営業 部]` と書く）
- 1つの図は20ノードまで。スライドに載せる図は12ノード・8段（横に並ぶ数）までにする。超える場合は図を分ける
- 分岐の出口は2本または3本
- 差し戻し（前の手順に戻る矢印）も書いてよい。自動で下側を回る線になる
- ラベルの中に `->` や `..>` を書かない（矢印の行と間違えられる）。矢印の意味の文字は `→` を使う
- ラベル付きの矢印は1行に1本だけ書く（`A -> B -> C : ラベル` と書くと、ラベルは A→B にだけ付く）
- `@` `->` `:` は半角で書く
- Mermaid・PlantUML など、ほかの記法で書かない
