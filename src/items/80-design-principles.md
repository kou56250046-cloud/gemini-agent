スライド JSON を作るときは、次の原則を守ってください。見た目（色・位置・フォント・文字の大きさ）は描画ツールが決めるので、あなたが決めるのは「何を・どの型で・どれだけ載せるか」です。

# 1. 1枚1主張
- `lead`（結論文）はそのスライドで一番言いたいことを1文で言い切る。60字以内
- 本文・図表は、lead の根拠だけを載せる。lead と関係のない情報は別のスライドか Appendix に回す
- 「〜について」「〜の状況」のような題名を lead に書かない

# 2. 空白を作りすぎない
- 描画ツールは、文字が少ないスライドでは文字を大きくし、行の間隔を広げて枠を埋める。ただし内容が薄すぎると間延びする
- 1枚の本文が2項目以下なら、近い内容のスライドとまとめるか、根拠（数値・具体例・条件）を足す
- box（右の囲み）を使うなら、3項目以上の中身を入れる。中身が少ないなら box を使わない
- 章扉（section）は章の区切りにだけ使う。1章1枚しかないなら章扉を作らない

# 3. 情報量の上限（超えたらスライドを分ける）
| 種類 | 上限 |
|---|---|
| bullets | 6項目（入れ子を含めて8行）。1項目60字以内 |
| table | 6行 × 5列 |
| issues | 5行 |
| flow | 12ノード・8段・レーン5本 |
| schedule | 期間12列・タスク10行 |
| summary | 4項目 |

# 4. 型を選ぶ
- 数値が3つ以上並ぶなら、文章ではなく table にする
- 手順・業務の流れは flow、日程は schedule、2案の比較は compare にする
- 選び方は「図表の選び方」に従う

# 5. 強調は少なく
- 1枚の強調は `**太字**` 3か所まで
- 強調するのは、lead の主張を支える数値や語だけ
- 全部を強調すると、どれも強調されない

# 6. 色・位置・フォントは書かない
- JSON に色コード・フォント名・座標・サイズを書かない（描画ツールの配色に統一される）
- 色で意味を伝えようとしない（「赤字の項目は〜」のような書き方をしない）。強調は太字で行う

# 7. 目次と章立て
- 章扉（section）が2つ以上あれば、描画ツールが表紙の次に目次を自動で入れる（章ごとにスライドの題名とページ番号が並ぶ）。toc を書く必要はない
- 目次で読み手が探せるよう、各スライドの `title` は中身が分かる名前にする（「その1」「補足」のような題名にしない）

# 8. 数値と言葉をそろえる
- 同じ数値はどのスライドでも同じ表記にする（「1,200万円」と「12百万円」を混ぜない）
- 単位は表の列名に書き、セルには数値だけを書く
- 数値には出典（`source`）を付ける
- 資料にない数字を計算で出したときは「試算」と書き、前提を note に書く。自分で整理した図・分類には「イメージ」「目安」と付ける
- 根拠の強さを超えて言い切らない（因果が分からないものは「〜の傾向があります」）
