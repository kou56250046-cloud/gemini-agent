資料・調べたこと・案件の状況を、読み手が 1 枚で分かるページにするときは、次の JSON を **言語名を `explain` にしたコードブロック**に入れてください。
見た目（色・フォント・配置）は gemini-agent が決めます。HTML・CSS は書かないでください。

```explain
{
  "title": "受注業務の見直し",
  "subtitle": "確認の時間を半分にするための進め方",
  "date": "2026-11-24",
  "audience": "営業部長",
  "conclusion": ["結論を 1 文で", "2 つ目", "3 つ目まで"],
  "overview": { "type": "flow", "caption": "現行の流れ", "src": "（フロー記法）" },
  "sections": [
    {
      "heading": "いま何が起きているか",
      "lead": "この節の言いたいことを 1 文で",
      "points": ["根拠や事実", "数値は出典と一緒に"],
      "figure": { "type": "map", "caption": "論点", "src": "（論点マップの記法）" },
      "table": "| 項目 | 現状 | 目標 |\n|---|---|---|\n| 確認時間 | 20 分 | 10 分 |"
    }
  ],
  "next": [{ "what": "締め日を決める", "who": "営業部長", "due": "2026-12-05" }],
  "notes": ["出典：〇〇（2026-11 時点）"]
}
```

# 型（この順番で読まれる）
1. **結論**（conclusion）：3 つまで。読み手がこれだけ読めば判断できる文にする。「〜について」で終わらせない
2. **全体像**（overview）：図 1 枚。type は flow（流れ）／arch（構成）／map（論点・案）／wbs（日程）／table（表）
3. **詳細**（sections）：結論 1 つに 1〜2 節。lead で節の結論、points で根拠
4. **次の一手**（next）：やること・担当・期限。担当と期限が決まっていなければ【要確認】と書く

# 守ること
- JSON の文字列の中の改行は `\n`、「"」は `\"` と書く。図の記法（src）も 1 つの文字列に入れる
- 太字は `**…**` だけ使える。HTML のタグは書かない
- sections は 5 個まで。1 節の points は 5 個まで
- 資料に無い数値を書かない。推測は【仮置き】
