作業を分解して日程を引くときは、次の表を **言語名を `wbs` にしたコードブロック**（```wbs で始めて ``` で閉じる）に入れてください。

```wbs
| ID | 階層 | 作業 | 成果物 | 工数(h) | 依存 | 担当 | 開始 | 終了 |
|---|---|---|---|---|---|---|---|---|
| 1 | 1 | 要件定義 | 要件定義書 |  |  |  |  |  |
| 1.1 | 2 | 現行業務の聞き取り | 議事録 | 16 |  | 担当A | 2026-12-01 |  |
| 1.2 | 2 | 要件の整理 | 要件一覧 | 24 | 1.1 | 担当A |  |  |
| 2 | 1 | 設計 | 設計書 |  | 1 |  |  |  |
| 2.1 | 2 | データ設計 | テーブル定義 | 24 |  | 担当B |  |  |
```

# 列
| 列 | 書き方 |
|---|---|
| ID | 1 / 1.1 / 1.1.1 の 3 階層まで。親子は ID の「.」で決まる |
| 階層 | 1〜3（ID の段と同じ） |
| 作業 | 動詞で終える（「〜を整理する」でも「〜の整理」でもよいが、表の中でそろえる） |
| 成果物 | その作業で何ができるか。**成果物の無い作業は作らない** |
| 工数(h) | 最下層の作業だけ書く（親は空。合計は自動）。数字だけ |
| 依存 | 先に終わっていないと始められない作業の ID（複数はカンマ）。親の ID を書くと、その親の全部の作業の後になる |
| 担当 | 人の名前か役割。決まっていなければ空 |
| 開始・終了 | yyyy-mm-dd。決まっている作業だけ書く。**空なら依存の後から工数 8h = 1 日で自動で引く**（土日は休み） |

# 守ること
- 最下層の作業は 8〜80 時間に収める。80 時間を超えるなら分ける。8 時間未満はまとめる
- 分け方は成果物で決める（「誰が」「いつ」で分けない）
- 依存は本当に先に終わる必要があるものだけ。何でもつなぐと全部が直列になる
- 祝日・休暇は計算に入らない。日付が決まっている作業（会議・承認）は開始・終了を書く
- 表の外に「前提（1 日 8 時間・人数・祝日の扱い）」と「リスク（遅れやすい作業）」を書く
- 工数の根拠（似た作業の実績・聞き取り）が無い数字は【仮置き】と書く
