システム・組織・データの構成を図にするときは、次の「構成図の記法」で書いてください。
座標・色・大きさは書かないでください。配置は gemini-agent が自動で行います。
記法は **言語名を `arch` にしたコードブロック**（```arch で始めて ``` で閉じる）に入れてください。

# 書き方
```arch
title 受注システムの構成
layer 利用者
layer 画面
layer 業務処理
layer データ
layer 外部
node U @利用者 営業担当 [person]
node W @画面 受注画面
node A @業務処理 受注API
node D @データ 受注DB [db]
node X @外部 基幹システム [ext]
group 社内ネットワーク : W, A, D
U -> W : ブラウザ
W -> A : HTTPS
A -> D
A ..> X : 毎晩 2 時
note A 入力チェックと在庫の引当
```

| 行 | 書き方 | 意味 |
|---|---|---|
| title | `title 題名` | 図の題名（1 行） |
| layer | `layer 層の名前` | 横の帯。書いた順に上から並ぶ。**先に全部の layer を書く** |
| node | `node ID @層 名前 [形]` | 層の中の箱。ID は半角英数字。形は省略できる |
| group | `group 名前 : ID, ID` | 点線の枠（ネットワーク・社内／社外・担当範囲などの境界） |
| 矢印 | `A -> B : ラベル` | 実線の矢印。ラベルは省略できる |
| 点線の矢印 | `A ..> B : ラベル` | 非同期・夜間・手作業の受け渡し |
| note | `note ID 補足` | 箱の下に小さく添える（1 つの箱に 2 行まで） |

形：`[box]`（四角・既定）、`[db]`（データベース・ファイル）、`[person]`（人・組織）、`[ext]`（社外・他部署のシステム。点線）

# 層の選び方（迷ったら）
- システム：利用者 → 画面 → 業務処理 → データ → 外部
- 組織・体制：決める人 → 取りまとめ → 実行 → 協力会社
- データの流れ：入力元 → 取り込み → 加工 → 保管 → 利用

# 守ること
- 1 つの層の箱は 5 個まで。多いときは層を分けるか、まとめて 1 つにする
- 箱の名前は 12 文字以内を目安に。説明は note に書く
- 矢印は 1 行に 1 本。`A -> B -> C` とつなげない
- 資料に無いシステム名・製品名を作らない。分からない箱は「（未定）」と書く
- `@` `->` `..>` `:` は半角で書く
