            使い方

            Gemini（Gem）と NotebookLM だけで、Claude Code のように段階を踏んで案件を進めるための道具です。 司令塔 Gem が 受付 → ヒヤリング → 仕様（ここだけ承認） → 作成 → 自己点検 → 修正 → 仕上げ の 7 段階で進め、このツールが応答を決まった見た目のファイル（文書・図・WBS・表・スライド・解説ページ）にします。

            3 つの使い方（どれから始めてもよい）

            ① HTML だけ

            拡張を入れられない・まず試したいとき

            • Gem の応答をコピーして「取り込み」タブに貼る
            • 図・文書・表が見分けられ、書き出しのボタンが出る
            • 何も入れなくてよい（この HTML を開くだけ）

            ② Chrome 拡張で自動

            毎日の案件を、コピペなしで回したいとき

            • 依頼を書いて押すだけ。送信・回収・保存を自動で繰り返す
            • 人の判断が要る所（仕様の承認・質問・書き込み）でだけ止まる
            • ファイルの横断検索・編集もできる

            ③ 会議・質問箱

            議事録や、資料への質問をまとめたいとき

            • Meet の字幕 → 文字起こし → 議事録・宿題の表
            • NotebookLM への質問と回答を、状態つきで管理
            • 決まったこと・未回答の質問は案件メモへ

            全体の流れ

            準備（最初の 1 回）

            1. 司令塔 Gem を作る「Gem 設定」タブの「司令塔 Gem」の指示文を、Gem の「カスタム指示」に貼る。知識ファイル（フロー記法・スライド JSON など）を .md で保存し、Gem の「知識」に入れる
            2. レビュー Gem も作る同じタブの「レビュー Gem」で、同じように作る（自己点検の段階で使う）
            3. 資料を NotebookLM にまとめる案件の資料はノートブックに入れておく。会話に添付するか、拡張なら NotebookLM に直接質問させる
            4. （拡張を使うなら）拡張を入れる下の「拡張で自動にする」の手順で入れる

            HTML だけで使う（毎回の流れ）

            1. 司令塔 Gem に依頼と資料を渡す質問には選択肢で答える。「全部仮置きで進めて」でもよい
            2. 段階 3 の仕様を承認する背景・受入条件・非目標・成果物・確かめ方を読み、「承認」か直す点を返す
            3. 応答を「取り込み」タブに貼る丸ごとコピーして貼ると、図・文書・表・スライドが見分けられ、行き先と書き出しのボタンが出る
            4. レビューと修正段階 5 のレビュー依頼文を、観点ごとに新しいチャットでレビュー Gem に渡す。指摘の表を司令塔に返して直させる

            直したいときは同じ会話で指示すると、変えた節だけが返ります。応答の 1 行目に「段階・型・次に人がすること」が出るので、迷ったらそこを見ます。

            Chrome 拡張で自動にする

            拡張を入れると、Gemini の画面の横（サイドパネル）にこの画面が出て「エージェント」「監査」タブが増えます。

            入れ方（最初の 1 回）

            1. zip を保存して展開右上の「Chrome 拡張をダウンロード」→ 展開した gemini-agent-extension フォルダを PC に置く（場所は変えない）
            2. デベロッパー モードをオンChrome で chrome://extensions を開き、右上のスイッチを入れる
            3. 読み込む「パッケージ化されていない拡張機能を読み込む」でそのフォルダを選ぶ
            4. 固定して開くパズルの印から「Gemini エージェント」を固定し、押すとサイドパネルが開く

            新しい版は同じ場所に上書きし、拡張機能の画面で「再読み込み」を押します。

            毎回の使い方

            1. 案件フォルダを選ぶ次からは自動で開く（許可を 1 回押すだけ）
            2. モードを選ぶ迷ったら「計画（読むだけ）」。調べて計画を出させ、承認してから書かせる
            3. 依頼を書いて「送って進める」例：「資料/仕様 の締め日の記載を、議事録の決定に合わせて直して」
            4. 止まったら答える黄色の枠＝質問、青の枠＝計画の承認、赤の枠＝書き込みの許可（差分を見て押す）

            パネルの見方（上から順に）

            場所何が分かるか
            状態の帯いま何をしているか（送信中・生成中・道具・許可待ち）と経過秒。上の細い線が段階 1〜7 の進み。止まった理由と次にすることもここに出る
            今日の確認期限切れ・今日まで・3 日以内の質問、会議の決定で答えが出ていそうな質問（「回答済にする」で閉じられる）、進んでいない日数
            モード・依頼・送るボタン毎回使う所。スクロールせずに届く位置にある
            案件メモ段階・次に人がすること・未回答の質問・決まったこと・成果物（新しい版だけ）・リンクと書ける場所
            編集の履歴Gemini が直したファイルの一覧。「元に戻す」で控えに戻せる
            実行ログ・設定手ごとの記録（本文は残さない）、上限の手数・通知の時刻・セレクタなど

            案件フォルダ（1 案件 = 1 フォルダ）

            案件フォルダは、拡張が記録を書き、次の日に読み返す場所です。選んでおくと、前回の続きから始められ、成果物が自動で溜まり、Gemini が資料を直接読めます。中身はこのフォルダにだけ書き、ブラウザや外部には残しません。

            案件フォルダ/
├─ 案件の設定.md    ← 人が書く（リンク・書ける場所）
├─ 資料/            ← 人が置く。Gemini は読める
│   ├─ 議事録/      ← 会議の文字起こし・議事録
│   └─ 取り込み/    ← 右クリックで保存したページ
├─ out/             ← 成果物（自動で保存）
└─ case/            ← 拡張の記録（触らなくてよい）
    ├─ note.json・status.md  案件メモ・今の状況
    ├─ 計画/          承認した・差し戻した計画
    ├─ 編集履歴.jsonl・_控え/  編集の記録と控え
    ├─ audit/         監査ログ（本文なし）
    └─ 会話/          会話の控え（設定で止められる）

            案件の設定.md（メモ帳で書ける）

            NotebookLM: https://notebooklm.google.com/notebook/…
司令塔 Gem: https://gemini.google.com/gem/…
レビュー Gem: https://gemini.google.com/gem/…
書ける場所: 資料/仕様, src
            • NotebookLM：この案件のノートブックに送る。開いていなければ開いてから送る。未登録でノートブックを 2 つ以上開いていると、取り違えないよう止まる
            • 司令塔 Gem・レビュー Gem：案件ごとの Gem。未登録ならパネルの設定の値を使う
            • 書ける場所：Gemini にファイルを直させてよいフォルダ。out/ はいつでも書ける。case/ は書けない

            案件メモの「リンク」欄に入れても、このファイルの該当の行が書き換わります（ほかの行はそのまま）。

            計画モード（まず計画、承認してから実行）

            Claude Code の plan mode と同じ考え方です。計画モードでは Gemini は読むだけで、書く道具は拡張が拒みます（Gemini の約束事に頼りません）。

            1. 「計画（読むだけ）」で依頼するGemini はファイルの一覧・検索・読み込み・NotebookLM への質問だけで調べる
            2. 計画のカードが出る目的・調べたこと・変更するファイル・作るファイル・やらないこと・確かめ方・戻し方。case/計画/ にも保存される
            3. 承認するか、直してほしい点を送る「承認して実行」で実行モードに切り替わる。「直してほしい点を送る」なら計画を出し直す。「やめる」で終わる
            4. 実行中は、書く前に毎回差分を見て許可計画にないファイルを書こうとすると、許可の枠に赤で「計画にないファイル」と出る

            選択肢で答える（提案）

            方針が分かれる所では、Gemini が選択肢とおすすめを出します。ボタンを押すだけで返事になります。どれも違うときは、下の欄に書いて送ります。

            小さな作業（成果物を作るだけ）なら「実行」モードのままでかまいません。既存のファイルを直す・まとめて調べるときは「計画」から始めると安全です。

            ファイルを直す・横断して調べる（拡張）

            やりたいことGemini が使う道具決まり
            フォルダの中を見る・読むlist_dir・read_filetxt・md・csv・json・xlsx・docx・ソースコードなど。PDF・pptx・画像は NotebookLM へ
            横断して探すsearch部分一致か正規表現。種類の絞り込み（md,js）・前後の行・docx/xlsx の中も。多すぎるとファイルごとの件数だけを返す
            文書・コードの一部を直すedit_file「この文をこの文に」で置き換え。差分を見て許可。文字コード（UTF-8・Shift_JIS）と改行は元のまま
            Excel のセルの値を直すedit_xlsx値だけ。書式・グラフはそのまま。数式のセルは許したときだけ上書き。.xlsm（マクロ入り）は書き換えない
            Word の文を直すedit_docx1 段落の中で、太字などの書式の境目をまたがない文だけ
            新しいファイルを作るwrite_file・renderout/ と「書ける場所」の中だけ。図・スライド・解説ページは render で決まった見た目に
            計算するrun_js隔離した場所で 3 秒まで。通信できない
            資料に聞く・点検させるask_notebooklm・review案件のノートブック／レビュー Gem（観点ごとに別のチャット）

            元に戻す

            書き換える前の中身は case/_控え/ に残り、「編集の履歴」の「元に戻す」で戻せます。戻す前の中身も控えに残すので、戻したことも戻せます。人が後から直していたら、戻す前に確認が出ます。

            横断の調査

            「探す → 読む → まとめる」を繰り返し、結論を out/調査_<題>.md に書きます。末尾には、拡張が記録した実際に読んだファイルと探した語が自動で付きます（Gemini の申告ではなく記録が根拠）。

            タブごとの役割

            タブ使う場面
            エージェント（拡張）依頼を送って自動で進める。案件メモ・今日の確認・編集の履歴
            取り込みGem の応答を貼って、成果物を見分けて書き出す（HTML だけのときの入口）
            文書・図・スライド・表・WBS・解説ページ取り込んだ成果物を個別に直す・書き出す。WBS は営業日で日程とクリティカルパスを引く
            会議Meet の字幕を記録（拡張）、または文字起こしを貼って、議事録・宿題の表を作る。記録してよいか、参加者に先に伝える
            質問箱NotebookLM への質問と回答を状態（確定・要確認・未確定・提案）つきで管理。新しい質問は自動で入り、回答が変わったときだけ差分を見て選ぶ
            監査（拡張）どこで・誰が・何を・どこまで進めたか。本文は入れず、書き換えは「検証」で分かる
            Gem 設定Gem の指示文と知識ファイル。拡張なら Gem の編集画面に流し込める（保存は人が押す）

            拡張では、Gemini の入力欄で /仕様 /続き /引き継ぎ などのあとに Tab で定型文になります。右クリックの「このページを案件の資料に保存」で、見ているページを 資料/取り込み/ に保存できます。

            Google への出口

            渡す先ボタン手順
            Google ドキュメントGoogle ドキュメント用にコピー新しいドキュメントに Ctrl+V。見出し・表・太字・フロー図（画像）が保たれる。崩れたら「.docx で保存」→ Drive にアップロード →「アプリで開く → Google ドキュメント」
            Google スプレッドシート表をコピー／.xlsx で保存コピーはセル A1 を選んで Ctrl+V。.xlsx は見出しの固定・フィルタ・罫線付き。Excel でもそのまま開ける
            Google スライドGoogle スライド向けに保存日本語を Noto Sans JP にした .pptx を Drive にアップロード →「アプリで開く → Google スライド」。PowerPoint で使うなら「PowerPoint で保存」
            NotebookLMNotebookLM 用 .mdソースに追加する。同じ名前の古いソースは先に削除する（古い版と混ざると回答が食い違う）
            Excel（VBA）コピー／.basAlt+F11 →［挿入］→［標準モジュール］に貼って F5（.bas は［ファイルのインポート］）。エラーが出たら、エラー文と止まった行を司令塔に貼る

            困ったとき

            こんなときこうする
            送っても動かない「つながりを確かめる」を押す。「入力欄が見つかりません」なら Gemini の画面の作りが変わっている。設定の「セレクタ」を直すまでは、応答をコピーして取り込みタブに貼る使い方ができる
            途中で止まった状態の帯の理由を読む。1 回の依頼は 20 手まで（設定で変更）、同じ道具の失敗が 3 回続くと止まる。続けるときはもう一度依頼を送る
            「どのノートブックか分かりません」案件の設定.md に NotebookLM の URL を書く（案件メモの「リンク」欄でもよい）
            「書ける場所の外です」直させてよいフォルダなら、案件の設定.md の「書ける場所」に足す。足したくなければ、そのまま断ってよい
            「Shift_JIS で書けません」Shift_JIS に無い字（一部の漢字・絵文字）が入っている。その字を使わないよう Gemini に頼むか、ファイルを UTF-8 で保存し直す
            直してほしくなかった「編集の履歴」の「元に戻す」。控えは case/_控え/ にもある
            フォルダを替えられない実行中・会議の記録中・質問箱の送信中は替えられない。終わるか「止める」を押してから選ぶ

            守ること

            • このツールと拡張はネットワークに出ません。Gemini と NotebookLM の画面に文を入れて、表示された応答を読むだけです
            • 案件の資料を渡すのは、会社で許可された Gemini（Workspace 版）と NotebookLM だけにする。自動で操作してよいかは社内の規程を確かめる
            • HTML だけで使うとき、貼った内容は保存しません（タブを閉じると消えます）。拡張では案件フォルダにだけ書きます
            • 書き込みの許可は、差分を読んでから押す。計画にないファイル（赤の表示）は特に確かめる
